# 数字孪生工业自动化控制平台

WPF / .NET 10 / Windows x64。默认进入平台首页，识别与分拣系统是已接入的业务模块。模块注册与扩展说明见 `MODULE_EXTENSION_GUIDE.md`。

## 打开项目

使用支持 .NET 10 的 Visual Studio 打开 `DigitalTwinIndustrialAutomationPlatform.slnx`，还原 NuGet 后编译运行。

```powershell
dotnet restore .\DigitalTwinIndustrialAutomationPlatform.csproj
dotnet build .\DigitalTwinIndustrialAutomationPlatform.csproj -c Debug
dotnet run --project .\DigitalTwinIndustrialAutomationPlatform.csproj
```

源码包不包含 SDK、NuGet 缓存或 bin/obj。新增 `System.Management 10.0.0` 用于 Windows 设备清单；图像依赖 `OpenCvSharp4`、`OpenCvSharp4.runtime.win`、`OpenCvSharp4.WpfExtensions`，均固定为 `4.13.0.20260627`。

## 一键发布与打包

项目根目录新增 `Publish.cmd` 和 `Publish.ps1`，用于生成 Windows x64 自包含免安装包。准备 .NET 10 SDK 和可联网还原 NuGet 的环境。

- **双击 `Publish.cmd`**：默认版本 `1.0.1`，完成后打开输出目录。
- **命令行指定版本**：在项目目录执行 `Publish.cmd 1.0.1`。
- **PowerShell 调用**：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Publish.ps1 -Version 1.0.1`。执行策略参数仅用于这次进程，不修改系统策略。

脚本自动调用 `dotnet publish`，配置为 Release、win-x64、包含 .NET 运行时、不裁剪、不合并单文件。检查主程序、.NET 运行库、WPF 及 OpenCvSharp 原生库后，把发布目录的全部内容打包到 ZIP 根目录，读取归档内容验证可打开，并生成 SHA-256 校验文件。发布失败或缺少依赖时以非零退出码结束，不生成正式发布 ZIP。

输出结构示例：

```text
artifacts/
  v1.0.1_日期时间_随机编号/
    publish/                          # 完整免安装程序目录
    DigitalTwinIndustrialAutomationPlatform_v1.0.1_win-x64.zip
    DigitalTwinIndustrialAutomationPlatform_v1.0.1_win-x64.zip.sha256
```

每次使用新目录，保留旧发布包，避免上一次的 DLL 混入新包。`artifacts/`、`publish/`、`bin/`、`obj/` 已加入 `.gitignore`，并从项目默认内容扫描中排除发布输出目录。

将生成的 **ZIP**（可附带 `.sha256`）上传到 GitHub Release 的 Assets，版本标签建议与脚本参数一致，例如 `v1.0.1`。脚本只生成软件包，不自动上传或发布 GitHub Release。使用者完整解压 ZIP 后运行 `DigitalTwinIndustrialAutomationPlatform.exe`，保留全部 DLL 和子目录。

发布脚本已用 PowerShell 7 实际完成 Windows x64 交叉发布与 ZIP 打包，并通过归档完整性、SHA-256、发布失败不打包及无效版本号拒绝检查。Windows PowerShell 5.1 与双击 CMD 入口尚需在 Windows 实机验证；生成的 Windows 程序也需实机启动和硬件联调。

## 相机搜索与连接

在识别模块使用 **采集 → 连接相机**（主工具栏也有入口），打开设备列表并刷新、选择、连接。显示名称、设备编号、接口、状态和设备路径；实际收到第一帧后才显示“相机已连接”。

- 直接支持普通摄像头、虚拟摄像头，以及安装了 DirectShow 采集驱动的工业相机。
- 系统清单中发现、但未提供兼容取流接口的工业相机候选会单独列出；此类行不可连接，需厂商 SDK 或兼容驱动。
- 纯 GigE/GenICam 或厂商专有设备不能仅依靠通用系统枚举保证发现和采集，需按品牌型号接入 SDK；不是所有工业相机通用驱动。
- 设备列表读取元数据，不依次打开每台相机。连接时才申请设备并验证采集。
- 保存稳定设备标识；每次取流重新解析当前编号。设备被拔出时提示重新选择，不静默切换到另一台相机。
- 所选设备统一用于预览、拍照和自动识别，载入产品类配方不会改掉当前选择。“断开相机”会停止采样/预览并释放设备，保留最后一帧与设备选择。
- 首次拍照、预览或自动运行时未选择设备，会自动弹出选择窗口；离线导入图片不需要相机。

详见 `CAMERA_SUPPORT.md`，当前 Windows 驱动枚举和真实取流尚需本机验证。

## 一、建立产品类

1. 从首页进入“识别与分拣系统”。
2. 点击 **拍照**，或在“产品建档”工具栏点击 **导入本地图像**（Ctrl+Shift+I）。本地图像支持 JPG/JPEG、PNG、BMP、TIF/TIFF，菜单“产品与机器人 → 从本地图像建档”也可进入。导入只读取原文件，不会修改电脑上的原图；一次选择一张产品照片。拍照会独占打开所选摄像头，丢弃启动阶段 5 帧，再取一帧；也可用保留的手动预览和采样功能。
3. 相机通过“采集 → 连接相机”选择；点击图像工具栏“滤波”“边缘”“轮廓”右侧的 ▾，分别在弹窗中设置滤波、算子、阈值、核大小及最小面积并保存；固定灰度阈值/区间下限也可在工作区调整。
4. 无论拍照还是导入本地图像，都点击 **滤波 + 轮廓测量**。程序按“原图 → 灰度化 → 所选滤波 → 所选阈值分割/边缘检测 → 可选边缘闭运算 → 外轮廓提取 → 面积与闭合周长”处理。恰好有一个满足最小面积的有效轮廓时才允许建档。
5. 在右侧 **产品类** 标签页填写自定义产品名称，点击 **目录** 选择保存根目录，再点击 **保存产品类**。
6. 为其他产品类型重复上述步骤。也可点击 **加载产品库** 选择单个产品类目录或包含多个类的根目录（扫描本层子目录）。

产品类列表提供上下和左右滚动条；“处理算法”列按内容自动扩展，可拖动列边界调整宽度，悬停可查看完整算法文本。滚动列表时上方建档输入和下方操作按钮保持可见。

每个产品类保存为独立目录：

```text
product_自定义名称_GUID/
  product.json    # 产品 ID、名称、参考面积/周长、采集尺寸、时间、完整处理配方
  original.png   # 原始照片，无损保存
  processed.png  # 滤波并标注轮廓和测量值后的图像
  binary.png     # 实际参与轮廓提取的二值图
```

目录写入完成后才成为正式产品类，不覆盖已有目录；当前库中不允许不同 ID 使用相同名称。参数变化、切换原图或进行其他图像处理会使建档测量失效，需重新测量后保存。

**载入样本** 会加载所选类的原图和处理配方；**移出产品库** 仅移除索引，不删除磁盘目录，可再次导入。产品类路径索引保存到本机，重启时自动恢复；磁盘目录被移动/删除后需重新导入。

面积使用 `Cv2.ContourArea`，单位 px²；周长使用 `Cv2.ArcLength(contour, true)`，单位 px。使用外轮廓，孔洞不扣除面积，不累计内轮廓周长。尚未进行物理尺寸标定。

## 二、连接机器人并自动识别

1. 完成并加载所有需要识别的产品类。当前自动任务使用库中的全部产品类。
2. 展开 **机器人连接与循环识别参数**，填写域名/IP（不含协议前缀）、TCP 端口、面积误差百分数、周长误差百分数和采样频率。
3. 点击 **连接机器人**，再点击顶部蓝色 **开始自动识别**。
4. 程序停止手动预览，独占打开摄像头，持续读取并丢弃非采样时刻的旧帧，按设定时刻执行测量、比较和发送。
5. 在 **运行记录** 中查看识别状态、面积、周长和发送状态。点击 **停止识别** 停止循环；**断开** 会先停止识别再关闭机器人连接。

匹配公式：

`面积误差 = abs(当前面积 - 参考面积) / 参考面积 × 100%`

`周长误差 = abs(当前周长 - 参考周长) / 参考周长 × 100%`

两项均不超过各自配置、且唯一匹配一个产品类时才识别成功并发送产品类型。若多个类同时通过，不擅自选择其中一个，记录为歧义并不发送。无目标、多目标、无匹配、分辨率不一致时也不发送。

每个类使用其保存的处理配方测量；相同配方只测量一次。自动阶段不会将主界面后来修改的处理参数覆盖产品类配方。训练与识别共用同一实现，避免测量方法不同。

本地图像可以直接离线建档，不需要连接相机或机器人。用于后续实时识别时，图片应来自相同采集条件。当前自动运行要求库中所有类使用相同的图像分辨率，会向摄像头请求该尺寸；驱动实际尺寸不同则不匹配。相机视距、视角、焦距、曝光、背景和照明也应保持一致。面积与周长两个特征不能区分特征相近的所有产品，应通过实际样本验证允许误差。

频率范围 0.1～20 Hz。任务串行运行，不重叠、不积压分析任务；处理过慢时跳过错过的采样时刻，实际频率受相机帧率、算法、网络和日志写入耗时限制。

**同一实物持续出现在画面中会逐周期发送**，本版按用户配置循环采样，尚未接入到料传感器、取走判断或去重。

## 三、机器人报文

采用 TCP 客户端发送 UTF-8 JSON 行报文。机器人/网关需要运行匹配的 TCP 服务端，并按 `productType` 或 `productId` 映射分拣程序。具体字段与分包规则见 **ROBOT_PROTOCOL.md**。

“已写入 TCP”不表示机器人已完成动作；当前没有 ACK 协议。连接断开或写入失败会停止循环，不自动重发和重连。离开模块时会等待停止自动采样及手动相机。退出平台则同时取消任务并立即关闭机器人连接，共用有上限的清理等待，详见下节。

### 本机模拟机器人

项目附带只打印报文的 Python 标准库服务端，不控制设备：

```powershell
python .\tools\robot_tcp_simulator.py --host 127.0.0.1 --port 5000
```

在平台填写 `127.0.0.1:5000`，连接后以真实摄像头运行即可查看收到的产品类型。模拟服务端已验证中文 UTF-8、拆包及粘包分帧。真实机器人需按 `ROBOT_PROTOCOL.md` 实现自己的服务端或网关。

## 四、运行记录与持久化

- UI 保留最近 300 条采样，完整采样记录（含未匹配、歧义、报文及特征）逐条写入 JSONL 日志。
- 停止后，在“运行记录”页点击 **导出完整运行日志**。
- 新版机器人参数、采样参数及产品目录：`%LOCALAPPDATA%\DigitalTwinIndustrialAutomationPlatform\recognition-automation.json`。
- 产品库索引：同目录 `product-library.json`；原图和产品类本体始终位于用户自选目录。
- 完整日志：同目录 `run-logs\run_时间_GUID.jsonl`，每次开始创建新日志。
- 旧视觉参数沿用 `%LOCALAPPDATA%\ProductIdentificationSorting\settings.json`，保留已有配置。

原有滤波、边缘、形态学、直方图、模板匹配、文件搜索及手动图像保存仍保留，可从菜单与图像工具栏使用。旧“运行检测 / CSV”功能是手动轮廓计数，不是新的自动识别运行日志。

## 快速退出

点击右上角 × 或菜单退出时立即停止定时器、取消采样/预览/拍照等任务，并关闭机器人 Socket，唤醒网络等待。相机、普通图像处理及读取任务并行等待，共用一次 **1.5 秒退出宽限期**；已完成时立即退出，没有固定延时。底层相机取帧或设备释放一直不返回时，不再无限等待，也不在另一线程强行释放仍被使用的相机对象。该上限针对应用等待普通后台任务的阶段，不承诺所有驱动环境下进程总退出耗时。

正在进行的产品保存（包括目录和索引）、图片保存、导出、已注册的日志落盘及配置保存仍等待完成，不受上述宽限期截断。关闭流程封闭写入入口后不启动新写入。慢磁盘或网络目录写入仍可能增加实际退出时间；不会通过强杀进程来截断保存。设置文件保存移到后台，不在最终关闭事件里同步写磁盘。

模拟验证覆盖阻塞任务、异常/取消、空闲立即退出、多个后台任务共用期限、超时后仍等待写入、写入失败释放等待及退出后拒绝新写入。实际 Windows 相机驱动和桌面退出仍需实机验证。DirectShow 的读取不能靠设置 OpenCV 的 `ReadTimeoutMsec` 通用解决；[OpenCV 文档](https://docs.opencv.org/4.13.0/d4/d15/group__videoio__flags__base.html) 将该参数限定于 FFmpeg/GStreamer 后端。

## 分类参数弹窗

不再使用一张长表编辑所有参数。首页、侧边栏和“参数分类…”按钮进入设置分类入口；每个入口打开居中于主窗口的独立模态弹窗。也可直接点击图像工具栏各处理按钮右侧的 **▾**，或“工具 → 参数设置”下的对应菜单。

| 弹窗 | 参数 |
| --- | --- |
| 滤波 | 滤波类型、平滑/微分核、高斯 Sigma、双边灰度与空间 Sigma |
| 边缘检测 | 算子、Canny 高低阈值或梯度阈值、微分核、LoG 平滑参数、边缘闭运算 |
| 轮廓提取 | 轮廓来源、对应分割/边缘参数、前景方向、最小面积 |
| 形态学 | 操作类型、核大小、灰度分割方式与阈值 |
| 模板匹配 | 通过分数 |

左侧主按钮执行图像处理，右侧 ▾ 仅打开参数弹窗，不先执行处理。不需要先打开图片也能设置。切换算法后只显示相关字段，例如 Canny 显示高低阈值，双边滤波显示两项 Sigma。核大小、微分核和高斯 Sigma 延续共用配置，弹窗内有提示。

弹窗从当前配置创建副本：**保存设置** 验证并写入本机后生效；错误留在弹窗内提示，保留输入；**取消**、Esc 或关闭窗口不应用；**还原本次修改** 恢复打开弹窗时的值。保存某类设置保留相机、其他处理类别及机器人配置。静态图像已有处理预览时保存后刷新当前处理结果；已有建档测量失效，需重新测量后再保存产品类。自动分拣运行期间不能修改处理配置。

## 滤波、边缘与独立阈值

全部滤波、边缘与测量入口统一先转换为 8 位单通道灰度图，彩色/BGRA 输入按 BGR/BGRA 转灰度处理，原始图像不被修改。“不滤波”也会输出灰度图。工具栏和图像处理菜单新增 **灰度** 预览入口；无需手动点击，后续处理会自动灰度化。轮廓及测量图使用灰度底图，最后转三通道仅用于绘制彩色轮廓和文字。

通过工具按钮右侧 **▾ → 分类参数弹窗 → 保存设置** 配置，再重新测量并保存产品类。也可使用“工具 → 参数设置”子菜单，或从首页/左侧“设置”进入分类入口。每个产品类可设置不同算法和阈值。载入样本会恢复该产品配置；自动分拣始终使用各产品 `Recipe`，不使用当前设置覆盖它。

| 配置 | 支持选项或范围 |
| --- | --- |
| 平滑滤波 | 高斯、中值、双边、均值、不滤波 |
| 一阶微分滤波 | Sobel、Scharr、Prewitt、Roberts |
| 二阶微分滤波 | Laplacian、LoG（高斯后拉普拉斯） |
| 轮廓来源 | 灰度阈值分割，或 Canny、Sobel、Scharr、Prewitt、Roberts、Laplacian、LoG 边缘 |
| 固定灰度阈值 | 0～255；大于阈值为亮前景，勾选前景反选后为暗前景 |
| 灰度区间 | 上下限各 0～255，包含端点；勾选反选表示选择区间外 |
| Otsu | 每张图自动求分割阈值；保存算法模式，固定阈值输入不参与处理 |
| 梯度幅值阈值 | 0～255，供 Sobel/Scharr/Prewitt/Roberts/Laplacian/LoG 使用 |
| Canny 高低阈值 | 0～255 且低 < 高；与灰度阈值、梯度幅值阈值独立 |
| 核与 Sigma | 平滑/LoG 核 3～31 奇数；Sobel/Laplacian/Canny 核 3/5/7；高斯 Sigma 0 自动；双边两项 Sigma 独立 |
| 边缘闭运算 | 可选，核为 3～15 奇数，用于连接小断点 |

弹窗按当前类别和算子显示适用参数，保留其他参数的原值。Scharr、Prewitt 使用固定 3×3 核，Roberts 使用固定 2×2 核。LoG 自带高斯步骤；若前级已选高斯，相当于两次平滑。二阶算法使用拉普拉斯绝对幅值阈值，不是零交叉实现。

微分中间结果保留浮点正负值，一阶用 X/Y 梯度幅值，二阶取绝对值，最终饱和转换为 8 位（不按每帧最大值归一化）。大微分核可能使强边缘饱和；阈值应结合实际图像调节。微分滤波和边缘算子可以组合，初次使用建议“高斯平滑 + Canny”，先保证轮廓闭合、有效产品数为 1。不同算子会改变参考面积与周长，改算法或阈值后必须重新测量建档。

`product.json` 的 `Recipe` 保存可读的滤波名、边缘算子名、分割模式和全部阈值、核、Sigma、闭运算参数。旧整数枚举和缺失新增字段的参数仍可读取；新版产品类使用 `SchemaVersion: 2` 并记录 `ProcessingPipeline: GrayscaleBeforeFilterV1`。旧版本 1 类可载入原图和参数，但不能直接参加自动识别，因为灰度化与非线性滤波的顺序变化可能改变面积和周长。请“载入样本 → 重新测量 → 使用新名称保存 → 移出旧类”，或先移出旧类后使用原名称保存。旧目录不删除、不覆盖。改变任一处理参数会使当前建档测量失效。自动阶段按完整配置分组计算，不会将仅阈值不同的产品类错误复用同一结果。

算法参考：[OpenCV 梯度](https://docs.opencv.org/4.10.0/d5/d0f/tutorial_py_gradients.html)、[Sobel/Scharr](https://docs.opencv.org/4.13.0/d2/d2c/tutorial_sobel_derivatives.html)。
